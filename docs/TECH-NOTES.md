## 1. 架构概览

- 后端：Hono + drizzle / better-sqlite3（WAL 模式），鉴权 `requireAuth` → `c.get('user')`，`users.role` 区分 `user` / `admin`。
- 前端：Vue 3 单页。**所有前端补丁都打在 `Player-*.js` 这一个 chunk 里**，通过 bind-mount 原地覆盖容器内的同名文件。
- 部署形态：`docker compose`，多个 `./patches/<file>:/app/<path>:ro` 单文件挂载。

**挂载的两类区别（很重要）**：

| 位置 | 改完是否即时生效 |
|---|---|
| `/app/dist/assets/*`（静态资源） | ✅ 即时生效 |
| `/app/dist/` 根下的单文件（`index.html`、favicon 三件套） | ❌ `docker cp` 只是临时覆盖，**必须 force-recreate 才持久** |
| 后端代码（`/app/server/*`） | ❌ 必须 force-recreate |

## 2. 产物与补丁机制

产物是**单行压缩文件**，文件名哈希不变、内容原地替换。由此引出三条纪律：

1. **本地 = 容器 = HTTP 三处内容必须一致**（同一份文件三个来源，任何一处不同就是部署没生效）。
2. 改前先拉线上基线对比；部署走带回归闸门的脚本，**禁止手工覆盖整份文件**。
3. 改完必须做结构自检（补丁块括号自洽）+ 三处校验。

⚠️ 单行文件用 `grep -c` 计数永远返回 1，要数出现次数必须用 `grep -o -F "串" | wc -l`。

⚠️ 验证脚本必须开 `Network.setCacheDisabled`：文件名哈希不变意味着浏览器会一直用缓存的旧 JS，
不开这个会得出"改了没效果"的**假结论**。

## 3. 键位系统

这是整个项目最复杂的部分。

### 逻辑键

统一 14 个逻辑键：`up/down/left/right`、`a/b/x/y`、`l/r/l2/r2`、`start/select`（**没有 l3/r3**）。
站点级默认按平台存，玩家级只存 diff，合并顺序：

```
硬编码默认 → __global__ 默认 → 平台默认 → 玩家 __global__ → 玩家该平台
```

### 三个必须知道的坑

**① 平台必须在模拟器启动前确定。**
如果平台只在"打开按键设置面板"时才被设置，那么"直接进游戏"这条主路径上平台会退化成 `__global__`，
导致站点默认键位从未真正下发到核心。修复要在 Portal 的 async boot 里、核心创建之前完成
「设平台 → 拉默认 → 合并」。

**② 用户 id 的来源必须全局唯一。**
曾出现「改了键保存后又不生效」：面板用内存态的 auth store 取 uid，而键位同步模块只从 localStorage 找，
两处来源不同 → uid 恒为 null → 服务端键位永远拉不回来，进游戏时还会被站点默认覆盖回去。

> 排查套路值得记住：同一份状态出现**两个来源**时，别顺着直觉猜，
> 先做「注入正确值前后的对照实验」把根因钉死再改代码。

**③ `options.retroarchConfig` 是开机快照。**
它只在创建实例时拷贝一次，开机后改键**不会回写**。所以"中途读它来断言键位是否生效"是赌运气，
必须重挂载核心后再读。

### 冲突去重

RetroArch 一个物理键只保留最后一次绑定，因此同号冲突必须去重。
优先级：玩家真改过 > 平台默认 > 全局默认 > 硬编码；同级按固定键序先到先得。

> 🔴 `0` 是合法按钮号，**绝不能当 falsy 处理**（判断空要用 `v === undefined || v === null || v === ''`）。
> 🔴 禁用端口不要用 `-1`，会让 wasm 崩溃、画布全黑——顶栏却是正常的，极易误判成 GPU 问题。

### 街机组合键（如 LT = 双手 / RT = 双腿）

Neo Geo 的宏只有 `AB / CD / ABC / BCD` 四个，写死在 RetroPad 上，**没有 A+C / B+D**。
所以这类组合只能在**前端输入层**合成，而且必须把物理 L2/R2 本身吃掉，否则核心宏会叠加进来。

合成时要区分两条路径：键盘/远端玩家按**逻辑键名**展开，真实手柄按**按钮号**展开；
展开时改的是虚拟手柄自持的数组，**绝不能动真实手柄的 buttons**。

平台门控必须做——PSX 的 L2/R2 是真扳机，绝不能被吃掉。

## 4. 联机架构

- **画面是 WebRTC P2P**：房主 `canvas.captureStream()` + 音轨推给每个客机，**不经过服务器**。
- **服务器只中继信令**：`offer` / `answer` / `ice`（按目标定向转发）+ `chat`（广播）。
- 客机只有 `<video>`，**没有 EmulatorPortal**，所以任何依赖 Portal 引用的功能在客机上都会静默失效。
- 席位模型：拦截 `navigator.getGamepads()`，槽位 k 映射为第 (k+1)P 的设备；只有按 START 才入座，投币不占位。

### 已知限制

**房主窗口必须保持可见。** 浏览器在页面隐藏时会节流/挂起 `requestAnimationFrame`，
模拟器核心随之停摆 → **客机画面冻结**。这是"推流"架构的固有约束。

因此推荐配置是**电脑当房主、手机当客机**；反过来（手机当房主）会同时叠加高 DPR 画布编码压力、
后台节流和耗电三个问题。

> 当前 ICE 只配置了 STUN、没有 TURN，跨 NAT 场景缺少兜底。

## 5. ROM 与 romset

### 「列表标题」≠「romset 名」

显示用的标题和模拟器实际匹配用的 romset 名是两回事。
改名要分清改的是哪个，否则会出现"列表看着对了但游戏跑不起来"。

### 判断名字对错的唯一可靠办法

让 ROM 真的跑起来看帧间变化与亮度，而不是比对文件名。

### romset 的「口径代次」

同一个游戏在不同模拟器/FBNeo 版本里，romset 定义可能属于不同代次。
**"别的模拟器能跑、我们跑不了"最常见的根因就是口径代次不同**，而不是 ROM 坏了。

定位方法：从压缩产物里挖出核心的下载与构造方式（不要靠猜），
再对照上游驱动源码确认该 romset 的期望内容。

## 6. 踩过的坑（通用版）

| 现象 | 真因 |
|---|---|
| 键盘没反应 | 焦点卡在 `<button>`，事件处理器过滤掉了 button/a/input |
| 补丁不生效但语法检查通过 | 补丁块被上一个 IIFE 吞掉（未就地闭合），只有结构自检能发现 |
| 投币记了 2 个 | 原生按键 + 手柄转键盘桥同时生效，双重驱动 |
| 改压缩 Vue 渲染函数后文字不更新 | patch flag 写在 children 内部了，必须在 children 之外 |
| drizzle 迁移没执行 | 迁移的 `when` 比上一条早，被静默跳过；加完要查迁移表确认 |
| production + HTTP 登录不了 | Cookie 带 `Secure` 被浏览器拒收 |
| 改完前端没变化 | 走的是 CDN 缓存（.js/.css 默认缓存数小时），要走局域网 IP 验证 |
| 无头浏览器里手柄没反应 | 无头造不出真实 Gamepad，**不能据此判定功能坏了** |
| CDP 注入了假手柄却绑不上键 | 窗口未聚焦时 rAF 被节流，绑定轮询根本没跑（需 `bringToFront` + 焦点模拟） |

> 🛑 测"保存/删除"类按钮**绝对不能真点**：线上链路是鉴权的，点一下就是真写数据库。
> 正确做法是在页面里把对应 API 与 `fetch` mock 掉，只验证接线与反馈。

## 7. 工具链注意事项

- 容器**没有 curl**（用 Node 内置 fetch）；带 `import` 的临时脚本用 `.mjs`；
  带 `better-sqlite3` 的脚本必须放在 `/app` 内才能跑。
- 本机 shell 可能设了代理，探测 localhost 端口会被代理拒绝——Node 的 fetch 不走代理，
  遇到"连接被拒"先换 Node 探一次再下结论。
- Python 读写产物一律 `encoding="utf-8", newline=""`，否则 CRLF↔LF 会造出**假差异**。
- 容器内数据库在 `/data/app.db`（WAL 模式），备份要连 `-wal` / `-shm` 一起。
- 自启 Chrome 做真机测试时，Chrome 会**随启动它的 shell 退出而被回收**，需要用常驻后台任务托管。
